# 共有ドライブへの直接転送(ポータル → Google 共有ドライブ「CIPNガイドライン作成」)

統括委員長の Mac を介さず、ポータル(AWS)が、提出物・出力・手順書を共有ドライブへ転送する。
仕組み: ポータルの Lambda が、統括委員長の Google アカウントで動く Apps Script の Web アプリ(`Code.gs`)へ、ファイルを送る。Web アプリが、共有ドライブにフォルダとファイルを作る。
接続情報(Web アプリの URL と合言葉)は、AWS Secrets Manager の `jascc-gl-portal/drive` に置く(コード、画面、Git に書かない)。

転送の内容と共有ドライブの構成は、これまでの `sync_drive.py` と同じである。

```
提出/総論/総論<項目>_<題名>/   原稿の全ての版(<日時>_<版ID末尾>_<ファイル名>)、状態.txt(状態・期限・提出者・査読コメント)
提出/SR/<CQ>_<名称>/           Minds書類(xlsx)、文献選択の別添(xlsx)。記録が変わったときだけ、同じ名前で置き換える(ドライブの版の履歴に残る)
依頼書/                        総論の依頼書(Word)
マニュアル/<対象>/             手順書(Word)
```

- 自動の転送: 1時間ごと(EventBridge)。変更のあったものだけを送る。接続情報がなければ、何もしない。
- 手動の転送: ポータルの「共有ドライブへの転送」(統括委員会・事務局)の「今すぐ転送」。または `set_drive.py sync`。
- 転送した内容は、ポータルの「作成経過の記録」(「共有ドライブへの転送」)に残る。ドライブからポータルへは戻さない。
- 共有ドライブのメンバーは、委員に限る。学生を含め、委員以外に共有しない。

## 設定の手順(統括委員長。1回だけ)

### 手順 1. ポータルを展開する(Mac)

```
git pull origin claude/sleepy-turing-a740xe
cd platform/portal/infra && cdk deploy --require-approval never --outputs-file ../out/outputs.json
```

(1時間ごとの自動の転送、接続情報の読み取り権限、Lambda の実行時間 300秒が入る。)

### 手順 2. 合言葉を作る(Mac)

```
python3 platform/portal/scripts/set_drive.py token
```

表示された文字列(43文字)を、手順 3 の `TOKEN` に貼る。チャット・メール・Git には書かない。

### 手順 3. Apps Script の Web アプリを作る(ブラウザ。共有ドライブの編集権限のある Google アカウントで)

1. https://script.google.com で「新しいプロジェクト」を作る。名前は「CIPN共有ドライブ受け口」。
2. `platform/drive_gas/Code.gs` の全文を、`コード.gs` に貼る。
3. 「プロジェクトの設定」→「`appsscript.json` マニフェスト ファイルをエディタで表示する」を ON にし、`platform/drive_gas/appsscript.json` の全文を貼る(高度な Google サービス Drive v3 と、公開の設定が入る)。
4. 「プロジェクトの設定」→「スクリプト プロパティ」に 2つ追加する。
   - `TOKEN` = 手順 2 の文字列
   - `ROOT_FOLDER_ID` = 共有ドライブの最上位のフォルダの ID。ブラウザで共有ドライブ「CIPNガイドライン作成」を開いたときの URL `https://drive.google.com/drive/folders/<この部分>` である。
5. エディタで関数 `checkSetup` を実行する。権限の確認が出たら、許可する。実行ログに「共有ドライブのフォルダ: CIPNガイドライン作成」と出れば正しい。
6. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。「次のユーザーとして実行」= 自分、「アクセスできるユーザー」= 全員。デプロイして、ウェブアプリの URL(`https://script.google.com/macros/s/.../exec`)をコピーする。

「アクセスできるユーザー」を「全員」にしても、合言葉が一致しない要求は全て断る。この Web アプリには、閲覧・削除・移動・共有設定の変更の操作がない。

### 手順 4. 接続情報を保存する(Mac)

```
python3 platform/portal/scripts/set_drive.py save <メールアドレス>
```

URL と合言葉を入力する(合言葉は画面に表示されない)。保存の後、接続の確認が自動で行われ、「共有ドライブ「CIPNガイドライン作成」に接続できました」と出れば完了。

### 手順 5. 最初の転送

ポータルの「共有ドライブへの転送」で「今すぐ転送」を押す(または `python3 platform/portal/scripts/set_drive.py sync <メールアドレス>`)。
数分後に「状態を更新」を押し、状態が「完了」であることと、共有ドライブにフォルダとファイルがあることを確認する。以後は、1時間ごとに自動で転送される。

## 運用

- `Code.gs` を直したとき: 「デプロイ」→「デプロイを管理」→ 鉛筆 →「新バージョン」。URL は変わらない。
- 合言葉の変更(漏れた疑いがあるとき): `set_drive.py token` で新しい合言葉を作り、Apps Script の `TOKEN` と、`set_drive.py save` の両方を更新する。
- 共有ドライブ側でファイルを消したとき: ポータルの「全てを送り直す」。
- 一時的な失敗(Google 側の制限など)は、状態に「完了(失敗あり)」と失敗した項目が出る。次の転送(1時間後)で、その項目だけを再び試す。

## うまくいかないとき

| 症状 | 確認すること |
|---|---|
| `接続できません: ... JSON でない応答` | 手順 3 の 6 で「アクセスできるユーザー」が「全員」か。千葉大学の Google Workspace の管理者の設定で、組織外への公開が禁止されていると「全員」を選べない。その場合は、統括委員長の Mac で `sync_drive.py` を使う(従来の方法。内容は同じ) |
| `認証できません` | Apps Script の `TOKEN` と、保存した合言葉が違う。`set_drive.py save` をやり直す |
| `ROOT_FOLDER_ID が未設定です` / フォルダが見つからない | 手順 3 の 4。共有ドライブの最上位のフォルダの ID か。Apps Script を動かす Google アカウントが、共有ドライブのメンバー(編集権限)か |
| 状態が「未設定」 | 手順 4 を行っていない、または Secrets Manager の `jascc-gl-portal/drive` がない |
| 「実行中」のまま | 15分たつと、次の転送が始められる |
